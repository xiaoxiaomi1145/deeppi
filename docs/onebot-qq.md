# QQ / OneBot v11 配置

Deeppi 用 OneBot v11 客户端连接 QQ，不负责 QQ 登录。连接方式参考 [OneBot v11](https://github.com/botuniverse/onebot-11) 的[反向 WebSocket](https://github.com/botuniverse/onebot-11/blob/master/communication/ws-reverse.md)、[反向 HTTP](https://github.com/botuniverse/onebot-11/blob/master/communication/http-post.md)和 [AstrBot 的 QQ 接入流程](https://docs.astrbot.app/platform/aiocqhttp.html)。先在你自己的 OneBot 实现中完成授权和 QQ 登录。本文字段是协议配置，不同客户端的界面名称可能不同。

## 连接步骤

在运行 Pi 的本机打开 `/deeppi` 打印的链接，打开 **Pi 会话设置 → QQ**。

| 项目 | 反向 WebSocket | 反向 HTTP |
| --- | --- | --- |
| Deeppi 接收地址 | `ws://127.0.0.1:6199/onebot/v11/ws` | `http://127.0.0.1:6199/onebot/v11/event` |
| OneBot 应配置 | 反向 WS 地址、同一访问 Token；客户端提供 `X-Self-ID`、`X-Client-Role` | HTTP 上报地址、签名密钥；客户端对原始请求体生成 `X-Signature: sha1=…` |
| 发送回 QQ | Universal 连接，或另设 API 连接；分离模式同时需要 Event 连接 | 在 Deeppi 填写 OneBot **HTTP API 地址**和它的访问 Token；不是上报地址 |

1. 输入**机器人 QQ 号**、协议、端口和对应凭据，配置允许的用户或群，保存。端口默认 `6199`，填 `0` 由系统分配；以页面显示的实际地址为准。
2. 点击「开始监听」，在 OneBot 填入上报地址。WS 支持 `Universal`，也接受独立 `API` + `Event`。HTTP 模式用回调签名认证，接收后返回 `204`，**不依赖 HTTP 快速回复**；OneBot 还须开启 HTTP API，供 Deeppi 调用 `get_login_info` 及发送消息。非本机 HTTP API 要求 HTTPS 和访问 Token。
3. 点击「测试连接」，Deeppi 检查 `get_login_info` 返回的账号是否匹配。确认显示「已连接」后再点「开启自动回复」。只监听不会发消息。改连接设置会关闭回复；要停用整个桥接可点「停止监听」。不要在端口转发到公网的情况下部署。

## 谁可以和模型聊天

- 允许/拒绝名单填写 QQ 号或群号，可用空格、逗号和换行分开。**黑名单优先**。用户和群可以分别设为允许全部或仅白名单；群聊同时需要通过用户和群筛选。
- 默认仅私聊打开，群聊要单独打开，且默认仅放行群白名单。群聊可选只回应 `@机器人`、指定前缀（例如 `/ai`）或所有通过筛选的消息。只回复符合触发条件的消息，不把同群其他流量当作模型历史。
- 对于**非 QQ 工具**，除普通准入条件外，当次发送者必须在**工具白名单**，工具还必须显式选中。当前可选的是本地时间和文本计数。QQ **不会获取 Pi 原生 Bash、文件、MCP 或 Web 会话工具**，工具白名单也不授予这些本机权限。

## 上下文、缓存和表情

- QQ 历史与 Web/TUI 原生会话完全分开。私聊按账号和发信者隔离；群聊可选「同群共享」或「按成员独立」。共享群历史会在发信者之间共用，因此不适合希望群成员互相隔离的场景。
- 可跟随 Pi 当前模型，或单独选择 QQ 模型，设置思考档位、QQ 附加系统提示词、上下文上限、压缩阈值、保留近期 token、最大回复、冷却和缓存策略。达到阈值后自动摘要旧轮次，优先保留近期上下文；估算可能与供应商实际分词有差异，模型窗口假定不超过 Pi 模型配置中的上限。也可在最近对话中单独清除聊天上下文。
- QQ 保留稳定的系统和历史前缀，会话、模型和可用工具组合使用各自的缓存标识；工具细节、媒体数据和临时传输信息不会反复写入历史。压缩请求和聊天用量分别统计。`短期`/`长期`只是给模型服务商的缓存选项，真实命中以服务商返回数据为准。修改模型、工具或摘要可能使旧前缀无法命中。
- 开启「表情收藏与发送」后，模型可用 `qq_save_sticker` 从**当前消息**中按编号收藏已收到的图片并附备注，用 `qq_list_stickers` 查该会话的本地编号和备注，用 `qq_send_sticker` 按编号发回当前会话。不能让模型填写下载 URL、任意读取本机图片、跨会话读取或指定其他收件人。QQ HTTPS 官方媒体域名与受限的内嵌栅格图片受支持；保存空间和条数有上限。清除聊天上下文不会清除表情。

QQ 配置、历史和表情保存在 Pi 用户数据目录的 `deeppi/qq/` 下，默认 `~/.pi/agent/deeppi/qq/`。凭据保存在本机私有配置，Web 不回显已保存值。停用监听可阻止新流量，但不会删除本地数据。实机接入仍需你自己的 OneBot 客户端、QQ 登录和可用模型。
